# Backend Contract

1. Locate the existing validation, normalization, authorization, lifecycle, and persistence seam.
2. Reproduce or distinguish the root cause before changing a contract.
3. Extend the canonical owner and avoid frontend fallback truth or duplicate storage.
4. Validate the input-to-readback path in a safe environment and clean up disposable data.
5. Add a new seam only when the existing system cannot own the behavior, and state why.

# Website Task Handoff

Read AGENTS.md and docs/process/agent-workflow.md, which own authority and lifecycle. This skill does not create a competing workflow.

1. Reconstruct the selected Task from current Notion fields, outcome, acceptance, boundary, named artifact headings and latest receipt; do not preload all history.
2. Reconcile evidence with accepted scope. Name the demonstrated cause or missing discriminator, owner and reusable seam.
3. For an unchanged admitted next boundary, update/read back the same Task and send its link plus one action to the verified existing role chat, subject to Ivan's direct authorization. Do not ask Ivan to copy the packet.
4. Return a new decision, missing destination/authority or unsafe expansion to Product. Do not invent another chat/subagent, schema or lifecycle store.
5. Explain meaningful results and decisions to Ivan in concise Russian. No mandatory eight-section shell or full next-role prompt.
6. Only when Ivan asks for a prompt, produce one English packet beginning ROLE: <ROLE> with Task link, outcome, named files/headings, boundary, preservation, validation, omissions, rollback and stop conditions. Use prompts/task-template.md; never create a prompt chain.

Do not implement another role's work while routing. Preserve accessible behavior, shared patterns and truthful evidence boundaries.

# Portfolio Workflow Skills

Role files define authority. These skills define repeatable procedures.

| Workflow | Use for |
| --- | --- |
| `architecture-audit` | ownership mapping, duplication, cleanup priorities, and durable plan boundaries |
| `backend-contract` | server, integration, authorization, persistence, and content-service slices |
| `content-evidence` | project facts, assets, metrics, aliases, and claim provenance |
| `design-system-audit` | visual inventory, shared primitives, catalog, and external-system assessment |
| `plan-writing-closeout` | active plans, checkpoints, source-of-truth reconciliation, and archive |
| `website-copy-content-pass` | visitor-facing copy and removal of weak or placeholder language |
| `website-design-audit` | page hierarchy, visual critique, interaction direction, and responsive intent |
| `website-frontend-design-system` | frontend implementation, interaction, responsive behavior, and reuse preflight |
| `website-prompt-handoff` | task-linked owner handoffs; full English packets only when requested |
| `website-qa-browser-regression` | browser, mobile, accessibility, build, and evidence discipline |

Keep repository commands, credentials, screenshots, real content, and deployment details in canonical project documents rather than in portable workflow instructions.

## Design Scope

The immediate owner is DESIGNER, with bounded DESIGN SYSTEM input on shared primitives/tokens when needed. Produce a reviewable proposal, not implementation code.

1. Define the non-chat information architecture: what a hiring reader sees first, project discovery, full case study, experience/about, contact and the placement or deferral of manifesto. Preserve existing stable URLs unless a separate migration is approved.
2. Audit representative active surfaces, existing tokens/components and Figma evidence. Separate intentional patterns, reusable behavior, obsolete presentation and missing evidence. Do not treat source inspection as browser proof.
3. Review typography across identity/hero, navigation, headings, prose, case-study captions/metadata and controls. Propose font roles, scale, line height, measure, weights and responsive behavior using real portfolio text. Check available/licensed fonts, necessary glyph coverage, readability and loading cost before recommending adoption. No paid font purchase is authorized.
4. Propose the minimum design system: semantic color/surface roles, typography, spacing/content-width/grid, border/radius/elevation, interaction states, focus and reduced motion. Cover only repeated primitives needed by the selected screens: navigation, links/buttons, project references/cards, case-study sections, media/captions and evidence viewer. Do not create an enterprise library or mandate a new catalog service.
5. Make an explicit reuse decision: consolidate existing primitives, establish small portfolio-owned replacements, or assess compatible external primitives. A minimal coherent system is mandatory; a wholesale external system and new dependencies are not pre-approved. Name which repeated patterns each new primitive replaces and where it belongs.
6. Present concrete desktop/mobile designs for the home, project browsing and one representative full case study, with enough media, interaction and responsive states to judge the direction. Avoid a prose-only aesthetic report. Exploration and accepted design must be distinguishable.
7. Curate source media with Figma file/node references, intended crop/sequence, caption/alt and claim boundary. Distinguish actual recorded interaction from newly authored demonstration motion. Motion may illustrate behavior but cannot invent product results.
